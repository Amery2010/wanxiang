# 可选运行时静态合批

作者GLB优先保留语义可编辑性。场景中很多小部件会形成独立网格，因此提供**独立导出模式**，不改写默认作品或内置配方。

```sh
python wx kit export-runtime --assembly world-scene-harbor --out workspaces/harbor-runtime
python tools/benchmark_runtime_exports.py
```

浏览器：质量页 → **游戏运行时 ZIP · 静态合批**。其输入是通过GLTFLoader重新读取的成功导出快照，不是已爆炸、独显、夜景或动画播放中的展示网格。

## 保护规则

收集装配层级中全部骨骼和绑定网格、关节/行程控制目标及后代、液压两端、动作目标；透明材质和morph对象也不参与静态组。仅将同材质的不透明静态面合并到世界空间批次，保留原节点及层级（几何移入批次后节点变为空组）。源模型不被原地修改。

变换应用到顶点和法线。保留原三角面和顶点色，不做破坏剪影的自动简化。Python与浏览器分别实现相同契约，并比较三角面与潜在提交数，实际GLB独立回读、运动和骨骼变形另有测试。

## 结果

| 文件 | 用途 |
|---|---|
| `runtime.glb` | 可独立加载的优化副本，动画/骨骼目标保留 |
| `runtime-map.json` | 批次、材质、原节点、三角范围与世界AABB；包含优化前后潜在提交数 |
| `source.assembly.json` | 原配方，便于重新制作和恢复作者版 |
| `inspection.json` | Python实际导出回读结果（CLI） |
| `selection-bounds.json` | CLI选取/粗筛辅助；明确不是封闭物理碰撞体 |

浏览器 ZIP 附带来源、映射和说明；运行时同样的 scene root 可以整体移动。已合批的单个原静态空节点不能再直接移动它的几何，要重新生成或在运行时自行重组。实际设备和目标引擎性能仍需单独验证。

## 代价

“潜在提交”按网格/材质划分，是CPU统计，不是硬件FPS。合批会把共享实例几何展开，可能增加GLB体积和显存；批次包围盒更大，视锥裁剪更粗。始终保留默认作者GLB和独立模式，接入目标游戏后根据性能测量选择，不宣称对所有平台更快。

没有强制Draco/Meshopt/KTX2以增加离线解码依赖；也没有声称实现全资产手工LOD、物理碰撞、任意动态合批或自动合成蒙皮。需要这些时，以目标产品预算另行制作。
