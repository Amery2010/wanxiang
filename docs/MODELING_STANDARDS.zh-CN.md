# 万象 3D · 程序建模规范

适用：当前登记条目及后续作者源

## 1. 资料依据与适用边界

本规范不是把某个软件的按钮列表当作通用行业标准。下表区分**官方资料的原则**与**本项目为了可验证性制定的工程约定**。Lowpoly 没有一个适用于所有物体、屏幕距离和平台的统一三角形上限；卡通也不是“统一平滑 + 描边”的单一算法。

| 编号 | 官方资料 | 本项目采用的原则 |
|---|---|---|
| S1 | [Unity：Mobile optimization tips for technical artists, Part I](https://unity.com/how-to/mobile-game-optimization-tips-part-1) | 面数应服务轮廓和可见形体；LOD、合批需要结合实际开销，不机械套用 |
| S2 | [Blender：Bevel Edges](https://docs.blender.org/manual/en/4.0/modeling/meshes/editing/edge/bevel.html) | 倒角控制高光与边缘读形；避免倒角重叠；保持原来的大平面 |
| S3 | [Blender：Weighted Normal](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/weighted_normal.html) | 根据面面积、角度等贡献法线；保留明确的锐边 |
| S4 | [Blender：Smooth By Angle](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/smooth_by_angle.html) | 以相邻面的角度定义平滑边界，而不是以颜色或世界坐标偶然重合定义 |
| S5 | [Blender：Subdivision Surface](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/subdivision_surface.html) | 支撑结构、折痕和边界控制决定细分后的外形；增加细分不自动等于品质提升 |
| S6 | [Three.js：MeshToonMaterial](https://threejs.org/docs/pages/MeshToonMaterial.html) | 卡通渐变图是非颜色数据；使用渐变图时应采用最近邻过滤，避免无意平滑分阶 |
| S7 | [Khronos：glTF 2.0 Specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) | 米制、右手坐标、Y 轴向上；明确的节点、法线、材质、骨架与动画数据契约 |

S2 的固定版本链接便于复核，最新 Blender 文档路径可能继续变动。本项目实现的是独立 JS/Python 程序建模内核，并未声称运行了 Blender 的修改器。

## 2. 作者源与风格契约

正式风格为“精制模块化 Lowpoly”。大形稳定、切面有意图、比例与层次清晰，比把所有组件做得更复杂更重要。人物、动物的有机连接需要自然过渡；机械壳板、铰链、门缝、装甲间隙不能被统一磨圆或封死。

一个 ID 对应一个可复用的语义对象。颜色、观察角度、Lowpoly/Toon/体素派生不能分别计为新资产。角色变体可以复用身体，但必须如实说明复用关系，不以配方数冒充独立拓扑族。

作者源是 `tools/foundation`、`tools/worlds`、`tools/frontiers`、`tools/repair39` 与 `tools/game410`。生成后的 `library` 是构建产物。用户覆盖在 `authoring/overrides` 持久化；修复必须能在重建后保留。禁止复活退役几何、保留已经弃用的生成路径，或用旧模型改名填充目录。

## 3. Lowpoly 形体规范

### 3.1 轮廓、层次与细节分配

先确认主体轮廓，再组织功能结构，最后增加可读细节。远观应辨认类别，近观应理解结构，而不是看到大量无关小凸起。曲面将截面分配给方向变化、关节转折和轮廓极值；平面不因为“看起来低模”就添加随机三角凹凸。石块可以有有组织的棱面，但不能以随机碎片遮掩主体缺失。

动物的耳朵、吻部、尾根必须与其生理方向和表情一致；人物的额头、颧面、下颌、手指分别控制。非设计意图的漂浮眼睛、脱离脸部的鼻子、插穿皮肤的配饰、断开的肢体判为视觉问题。保留有功能意义的小间隙，例如手指间隙和独立的机械关节。

### 3.2 倒角与硬表面

倒角是主体的闭合边界，不是叠加一组互相穿插的面片。盒体保持六个平面，再构建十二条边和八个角；半径必须被物体最短边限制。薄门板不能使用会吞掉板面的“大圆角”。尺寸、铰链原点和接触面不随倒角变化。

当前倒角盒的 Lowpoly 路径使用 44 个三角形；Toon 路径使用 92 个三角形和解析法线。这是本项目这个算子的实现值，不是所有盒子或所有平台的行业标准。

### 3.3 法线

平面与轮廓同时验收：仅修复法线不能掩盖坏拓扑，仅增加几何也不能替代正确法线。Lowpoly 默认保留有意的切面；卡通或明确标注的曲面才在连续岛内平滑。

连续岛必须满足：属于同一个作者形体、沿实际共享边相连、该边只有两个相邻面、夹角小于对应阈值。仅一个点相碰不能传播平滑；颜色不同也不应自动切断平滑。同位的鼻子、脸、金属装饰不能因位置相同就被平均到同一法线。

当前采用面面积 × 顶点角度的加权贡献；Toon 有机形体默认 70°、硬面多面体默认 35°，作者可在 0–89° 内覆盖。这些阈值是起点，不是无需审查的万能参数。解析圆角盒另有精确法线，避免板面鼓包。

## 4. 卡通专用规范

### 4.1 几何风格

卡通要同时控制体积、轮廓节奏、锐边和分阶光照。不能对整个模型统一 Catmull/Loop 式圆滑，也不能把眼睛、耳朵、门缝、握柄一起融合。圆润程度按作者形体控制，支撑截面负责保形，独立动作部件保持原来的节点与控制轴。

`style_overrides.toon` 只允许覆盖 `roundable`、`smooth_angle`、`roundness`、`sides`、`rings`、`outline`、`bevel`。不接受任意键注入作者结构。局部圆滑程度与全局圆滑滑杆共同作用，不能让局部覆盖无意禁用滑杆。解析圆角盒不能再次进入普通细分，避免双重圆滑与接口缩小。

### 4.2 光照分阶

分阶依据应与物体表面的受光关系有关，而不能对最终 RGB 亮度做统一阈值。否则相同法线的深色和浅色表面会落到不同分阶，形成依赖颜色的脏块。

本项目在直射漫反射照明阶段、乘底色之前按 `N·L` 分三档。阈值为 0.25 / 0.65，档位为 0.13 / 0.50 / 0.97；连续的间接光和镜面反射不被这一档位量化。这里不是官方 `MeshToonMaterial` 的直接替换，而是保留项目 PBR 材质角色的受控着色补丁；Three.js 升级后必须重新验证着色块契约。

CPU 展示图采用相同分阶常数，但只是实际 GLB 的不透明顶点色、正交光照与 PCF 阴影近似。不能把它标成 Cycles、路径追踪或完整 GPU PBR。

### 4.3 导出兼容性

GLB 带走真实几何、法线、材质角色、节点、可用动画与元数据；标准 glTF 没有一个要求所有引擎实现相同自定义 Toon 分阶的通用内核字段。外部引擎会先获得核心 PBR 回退。项目查看器重新应用自身 Toon 着色。外部游戏要复现分阶，应显式移植该着色逻辑，不能只靠 `extras` 就声称跨引擎外观完全一致。

## 5. 程序网格与拼接规范

### 5.1 拓扑检查

每个作者形体独立审计，不跨形体强制焊接。检查有限数值、零面积三角形、重复三角形、超过两个面的非流形边、相邻面绕序冲突、闭合实体负体积和非单位法线。审计的坐标合并精度为 `1e-7 m`。

开放边界应报告，但不能一律判错：披风、叶片、插口与显式连接截面可以合法开放。只有声明为实体的部位才应该要求闭合。开放薄片的正反面处理和厚度由用途决定，不能偷偷把它改成体积盒。

狭长三角形以归一化质量量度 `q < 0.01` 记录，作为复核线索而非一票否决。窄缝、天线和真实小倒角可能自然产生狭长面。当前审计不等于所有任意三角形组合的精确全局自相交证明。

### 5.2 扫掠、尾巴和绳索

截面坐标系应沿中心线连续传输，避免参考轴接近 X 轴时突然翻转。使用旋转最小化的平行传输帧；显式的 `frame_axis` 必须符合形体实际方向。闭环需要周期切线和闭合扭转校正，不能把首尾重复截面再各封一个端盖。

### 5.3 配对接口

通过显式语义接口配对，而不是按全模型距离阈值焊接。接缝的顶点、端点、法线和蒙皮权重分别检查。配对两侧的端环和细分边中点必须对齐；锁定端点后不能用全包围盒重新缩放把它们移开。

孤立部件保留独立使用所需端盖；组合后只移除明确配对端盖。机械缝隙与独立铰链不能因为“无缝”要求而消失。蒙皮权重必须保持归一化，不以一个节点重命名为“骨骼”代替真实蒙皮。

## 6. 参数、单位与动作

单位统一为米、右手系、Y 向上；工程前向与 glTF 的约定一致。原点服务交互而非视觉居中：人物以既有语义落脚位置为基准；门用铰链；轮用轴心；机械行程沿声明的轴。

参数应表达身高、宽度、握持、行程等真实形态关系。至少检查默认值、声明端点和代表性组合；任何几何重建失败都应保留最后一个有效对象。复杂参数空间本轮并非穷举所有组合。

必须保留当前 ID、引用关系、骨骼名称、插槽、控制器与动画通道。肘、腕、膝的几何/权重拼接与铰链变换分别测试。静态合批不能吞掉骨骼、运动目标或透明对象，也不能把合批结果冒充可逆的作者源。

## 7. 性能与交付

本项目已有每部件 30,000 三角形、装配 400,000 三角形等构建保护上限；这些是防失控护栏，不是目标预算或性能认证。核对实际三角形、导出顶点、材质、网格、骨骼、节点和提交数。由于颜色与法线拆分，导出顶点数可以显著大于几何位置点数。

默认不为所有低模强行生成多级 LOD。静态合批减少潜在提交数，但可能增大包体和内存并扩大裁剪范围；不把提交数改善直接写成 FPS 改善。纹理仅保留运行用途明确的资源，不能用巨大历史材质包遮掩形体问题。

导出文件必须经过真实回读；独立读器和浏览器加载不是同一层验证。出包后检查 ZIP CRC 与 SHA-256 封闭清单，再在干净目录验证关键入口。没有执行的官方 Khronos 验证器、真实手机和实体 GPU 测试，明确写“未执行”。

## 8. 视觉复核规则

默认八视角用于定位倒面、漂浮部件、遮挡与轮廓失衡。总目录接触表用于筛查全库的明显异常；关键重建部件另做前后同相机、同尺度、同光照对照。两版分别居中放大到一样大小会掩盖真实尺寸变化，因此对照使用共同包围盒。

低质量记录包括：稳定 ID、作者路径、问题形体索引、证据、技术/视觉分类、处理方式、复查结果、剩余边界。不得把“通过技术检测”写成“601 项全部达到审美满分”。颜色、面数、着色和拓扑统计应分开呈现。

## 9. 可执行入口

```sh
# 作者源重建（保留显式用户覆盖）
python tools/rebuild_library.py --overwrite
# 当前游戏扩展的几何与参数检查
python tools/check_game410.py
# 当前单层缩略图、索引和源指纹
python tools/verify_game410_previews.py
# 核心回归与作者事务检查
python -m pytest tests/test_game410.py tests/test_advanced_lowpoly39.py tests/test_geometry.py -q
python tools/rebuild_acceptance.py
pnpm dev
```

浏览器检查需要本地 Chromium/Playwright；清理阶段未重跑浏览器或 E2E。脚本与 CPU 诊断图不能代替移动真机、实体 GPU 或目标游戏验收。
