# 生产组件运行时协议

## 1. 来源、坐标和实例

正式定义位于 `library/parts`／`library/assemblies`，作者源位于 `tools/expansion/`、`tools/l34_expansion/` 和 `tools/game410/`。ID 不随配色、风格、镜像参数和 LOD 改变。单位为米，+Y 向上，+Z 为名义前向；关节组件以真实安装轴为局部原点，不自动“归一化至脚底”。场景装配使用显式局部位置、旋转、正缩放和父子关系。

导出保持稳定节点名。子装配节点在展开后使用路径前缀，例如 `lift.deck`、`arm.elbow`。不要只取末尾名字查找节点，也不要通过模型外观猜测原点。左右机翼通过 `side=left/right` 的轮廓和绕序生成，不通过负实例缩放把翼型上下翻转。

`enabled` 是解析后必须为布尔值的作者形体开关；false 在接缝、细分和法线计算前移除对应几何。它不是渲染时隐藏网格，也不是“把 LOD 文件重命名”。全部形体禁用仍属于无有效模型错误。

## 2. 端口连接

使用阶段 B 的 15 类版本化接口。兼容查询给出默认参数候选；最终装配重新验证实例的世界尺寸、方向、版本和容差。`attach` 是真实装配约束，不只是检索标签。

```json
{
  "id": "nextRail",
  "part": "exp.transport.rail_straight",
  "attach": {
    "target": "firstRail",
    "own": "in",
    "socket": "out",
    "mode": "opposed"
  }
}
```

铁路按 1.435m 两条钢轨内缘距离定义轨距，不能把中心距直接当轨距。直轨端面不在接缝处倒角；弯轨端截面使用解析切线；道岔分支由真实中心线切线定位。管道端部有真实内腔与法兰平面，弯管端截面不使用离散最后一段替代真实端部法线。

## 3. 刚性机构与 GLB 动画

`library/motions/*.json` 的轨道允许以下两种之一，不能同时出现：

```json
{
  "name": "Platform lift",
  "duration": 5,
  "tracks": [{
    "node": "deck",
    "axis": [0, 1, 0],
    "translations": [0, 0, 2.55, 2.55, 0]
  }]
}
```

旋转轨道使用 `degrees`，导出为四元数 `rotation`；平移轨道使用 `translations`，导出为 `VEC3 translation`。平移是在静止局部变换下计算的位移：`T(t) = T_rest + linear(M_rest) × axis × displacement(t)`，因此旋转或缩放过的子装配仍沿自己的轴运动，不覆盖静止平移。非法轴、非有限数、时长或数组会被拒绝。

装配和工作区递归收集子装配动画，轨道目标与动画名称使用命名空间。未登记的 `--spec` 工作区同样可以保留其子装配动画。动画片段相互独立；没有自动将不同片段混成整套行为树。

根控制器可以有静态状态滑杆，不是所有滑杆都会自动生成循环动画。例如操作臂保留肩／肘／夹爪状态控制，同时提供有限演示片段，不能把它称作 IK 抓取控制器。

## 4. 骨架与服装

八个角色复用已有 15 骨骼人体；服装、背包、头盔和持物按骨骼挂装。蒙皮和逆绑定矩阵保留在 GLB 中。蛇与触手使用连续分段权重；骷髅骨块则有意刚性绑定单骨，避免把骨头本身弯软。鸟翼、尾部、机器人多采用刚性关节。

装备检查套件用于浏览、选择和组合，不是另外一套完整角色，也不提供自动体型适配所有外部模型。布料、表情、脚底锁定、通用重定向和完整游戏动作库不在本次交付中。

## 5. 碰撞、触发和交互分别处理

浏览器导出 `wx.collider-recipes/1.0`，CLI 导出 `wx.collider-set/1.0`。两者均明确 `selection_bounds_are_colliders:false` 和 `engine_adapter_required:true`。

- `instances`：每个来源部件的局部碰撞意图、参数、LOD、交互和辅助标记；CLI 还包含世界矩阵与显式请求的网格代理。
- `assembly_colliders`：装配级胶囊等覆盖代理。`child_collision_policy:replace-children` 表示不要同时创建被覆盖子树的重复碰撞。
- `assembly_interactions`：递归命名的装配事件、触发区与碎片节点。

若 CLI 网格代理已应用尺寸参数，消费端只应用对应世界矩阵，不能再次重复乘参数比例。浏览器轻量配方通过同名 GLB 节点获取变换。动态关节的碰撞和触发区必须跟随当前节点变换，不能一直使用静止世界坐标。

```json
{
  "schema": "wx.interaction/1.0",
  "kind": "breakable",
  "authority": "consumer-game",
  "event": "crate.break",
  "trigger": {"shape": "none"},
  "fragments": ["bottom", "top", "front", "back", "left", "right"]
}
```

`kind` 和 `event` 是消费端意图，不会自动执行游戏逻辑。检查点、占领点、钥匙、门锁、传送与发射器用不同的事件与触发形状。触发区有独立尺寸，不复用可见模型包围盒。可破坏木箱使用六个面板，墙使用十二个块；某些危险桶明确标为 `fragment_policy:consumer-generated`，不会假称已导出几何碎片。

FX 挂点的 `helper_only:true` 表示调试／发射代理。消费端通常读取后隐藏其可见辅助网格，再创建自己的粒子效果。源 GLB 不烘焙大量粒子，编辑器也不会自动运行粒子或玩法服务。

## 6. 运行时合批

静态合批不等于减面。保留节点名称和源范围映射，并保护蒙皮、动画、状态控制、透明对象以及显式碎片与 FX 辅助节点。不得为了减少 draw call 把碎片烘成一个不可拆网格，或把发射标记并入地面导致无法单独隐藏。

导出后仍需目标引擎验证碰撞层、静态／动态网格限制、胶囊缩放、LOD 切换、视锥裁剪与真实设备性能。本项目没有据潜在提交次数直接推算 FPS。
